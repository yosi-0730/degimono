# ラズパイ 構築・運用手順書

在庫管理システム（Flask + SQLite + MQTT）をラズパイ上で動かすための手順書です。**機能追加・仕様変更のたびに更新**してください（末尾の「更新履歴」に追記）。

> ⚠️ 本書の手順は、まだ実機のラズパイで通しで検証していません。実機で試した結果は「9. 検証状況」に反映してください。

---

## 1. 前提・構成

| 項目 | 内容 |
|---|---|
| 機種 | Raspberry Pi 3B+ / 4 / 5 推奨（Zero系は非推奨） |
| OS | Raspberry Pi OS (64bit) Bookworm 以降 |
| ネットワーク | 有線LAN推奨。M5StickC・業務PCと同じLANに接続 |
| 構成 | Web画面+API（ポート5000）、MQTTブローカー Mosquitto（ポート1883）、DB は SQLite（`data/degimono.db` の1ファイル） |

**起動方法は2通り。どちらか一方を選ぶ。**
- **方式A: Docker**（推奨）… `docker compose up` だけ。Mosquittoも同時に起動。
- **方式B: Dockerなし**… venv + systemd。軽量。

## 2. ラズパイの初期準備（共通）

1. Raspberry Pi Imager で Raspberry Pi OS (64bit) を書き込む。設定画面でホスト名（例: `degimono`）、ユーザー名/パスワード、WiFiまたは有線、**SSH有効化**、ロケール（`Asia/Tokyo`）を済ませる。
2. 起動後、PCからSSH接続して更新する。
   ```bash
   ssh <ユーザー名>@degimono.local
   sudo apt update && sudo apt full-upgrade -y
   ```
3. **IPアドレスを固定する**（M5StickCがラズパイを見つけられるようにするため）。
   - 推奨: ルーターのDHCP設定で、ラズパイのMACアドレスに固定IPを割り当てる（予約）。
   - ルーターで設定できない場合は、ラズパイ側で設定（例: 有線）:
     ```bash
     nmcli con show                       # 接続名を確認
     sudo nmcli con mod "<接続名>" ipv4.method manual \
       ipv4.addresses 192.168.x.x/24 ipv4.gateway 192.168.x.1 ipv4.dns 192.168.x.1
     sudo nmcli con up "<接続名>"
     ```
   - M5StickC には `degimono.local` ではなく**固定IP**を設定する（mDNS名はM5側で解決できないことがあるため）。

### 2.1 実機の接続情報（記録）

| 項目 | 内容 |
|---|---|
| ホスト名 | `raspberrypi`（mDNS: `raspberrypi.local`） |
| ユーザー名 | `raspi` |
| OS / 機種 | Debian 12 (bookworm) 64bit / aarch64、メモリ 8GB |
| タイムゾーン | Asia/Tokyo（設定済み） |
| 有線LAN（eth0） | PCと直結用に固定IP `192.168.50.2/24`（nmcliで手動設定） |
| Wi-Fi（wlan0） | `10.9.2.231/24`（DHCP。PC側Wi-Fi `10.22.x.x` とは別セグメント） |
| PC側（イーサネット） | `192.168.50.1/24`（直結用に手動設定） |
| SSH接続 | `ssh raspi@192.168.50.2`（PCの `id_rsa.pub` を登録済み・鍵認証） |
| アプリ配置先 | `/home/raspi/degimono` |

> 直結の経緯: PC Wi-Fi とラズパイ Wi-Fi が別ネットワークで通信できず、LANケーブル直結＋固定IP（192.168.50.x）で接続した。`raspberrypi.local` は PC の `ssh` から名前解決できなかったので IP 直指定。
> M5StickC に設定する「固定IP」は、運用する実LAN側のIPで別途決める（上記 192.168.50.2 は直結用の暫定値）。

#### 直結の設定方法（PC側）：「代替の構成」を使う（採用）
PC の `イーサネット` は **DHCP（自動取得）のまま** にして、「代替の構成」に直結用の固定IPを登録する。DHCP のあるLANでは DHCP で IP が付き、DHCP がない直結のときだけ代替の構成の `192.168.50.1` が使われる。ケーブルを差し替えても設定変更は不要。

**設定手順**（管理者権限が必要）
1. （すでに固定IPを付けている場合のみ）管理者の PowerShell で DHCP に戻す。InterfaceIndex は `Get-NetAdapter` で確認（2026-10-21 時点は 21）。
   ```powershell
   Remove-NetIPAddress -InterfaceIndex 21 -IPAddress 192.168.50.1 -Confirm:$false
   Set-NetIPInterface -InterfaceIndex 21 -Dhcp Enabled
   ```
2. 「ネットワーク接続」（`ncpa.cpl`）→ `イーサネット` を右クリック → プロパティ → 「インターネット プロトコル バージョン 4 (TCP/IPv4)」→ プロパティ。
3. 「IP アドレスを自動的に取得する」を選ぶと **「代替の構成」タブ** が出る。
4. 「代替の構成」→「ユーザー構成」→ IPアドレス `192.168.50.1`、サブネットマスク `255.255.255.0`（ゲートウェイ・DNS は空欄）→ OK。

**確認**: 直結したまま `Get-NetIPInterface -InterfaceIndex 21 -AddressFamily IPv4` で `Dhcp` が `Enabled`、`ipconfig` で `192.168.50.1` が付いていること。DHCP が応答しない状態から IP が付くまで、ケーブルを挿して **1分ほど** かかることがある。

> ⚠️ 2026-10-21 時点では、この方式は実機で未確認（Windows 標準機能だが、本環境での動作確認はまだ）。確認できたらここを更新する。
> 参考（採用しなかった方式）: `New-NetIPAddress` で固定IPを付ける方法は、DHCP が無効になり、別のLANへ挿し直すと通信できなくなる。戻すときは上記の手順1のコマンドを使う。
> ラズパイ側（eth0 の 192.168.50.2）は、実LANへ接続するときに 2章の3 の手順で実LAN用の固定IPへ変更する（直結用のままだと実LANで使えない）。

## 3. アプリのラズパイへの配置（共通）

Windowsの PowerShell で、プロジェクト（`degimono`）フォルダから実行。`docs/`・`.venv/`・`old_prototype/`・`data/` は不要。

```powershell
ssh <ユーザー名>@<ラズパイIP> "mkdir -p ~/degimono"
scp -r app.py index.html m5_dummy.html requirements.txt Dockerfile docker-compose.yml .dockerignore mosquitto <ユーザー名>@<ラズパイIP>:~/degimono/
```

## 4. 方式A: Docker で動かす

### 4.1 Dockerの導入（初回のみ）
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 一度ログアウトして入り直す（または再起動）
docker --version && docker compose version
```

### 4.2 起動
```bash
cd ~/degimono
docker compose up -d --build
docker compose ps                     # web / mosquitto が Up であること
docker compose logs -f web            # ログ確認（Ctrl+Cで抜ける）
```
- DBは `~/degimono/data/degimono.db` に作られ、初回のみデモ部品・従業員が投入される。
- 自動起動: `restart: unless-stopped` と Docker の自動起動により、ラズパイ再起動後も立ち上がる。
- 停止: `docker compose down`（DBは `data/` に残る）

### 4.3 本番運用の前に（デモデータを入れない）
`docker-compose.yml` の `# SEED_DEMO: "0"` のコメントを外してから**初回起動**する（従業員マスターは常に投入される）。すでにデモデータが入っている場合は「8.3 DBの初期化」を参照。

## 5. 方式B: Docker なしで動かす

### 5.1 パッケージ導入
```bash
sudo apt install -y python3-venv mosquitto mosquitto-clients
```

### 5.2 Mosquitto の設定（LAN内のM5からの接続を許可）
```bash
sudo tee /etc/mosquitto/conf.d/degimono.conf >/dev/null <<'EOF'
listener 1883
allow_anonymous true
EOF
sudo systemctl enable --now mosquitto
sudo systemctl restart mosquitto
```

### 5.3 Python環境
```bash
cd ~/degimono
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 5.4 常駐化（systemd）
`/etc/systemd/system/degimono.service`（`<ユーザー名>` は置き換える）:
```ini
[Unit]
Description=Degimono inventory web
After=network.target mosquitto.service

[Service]
User=<ユーザー名>
WorkingDirectory=/home/<ユーザー名>/degimono
Environment=TZ=Asia/Tokyo
Environment=MQTT_BROKER=localhost
ExecStart=/home/<ユーザー名>/degimono/.venv/bin/gunicorn -b 0.0.0.0:5000 --workers 1 --threads 4 app:app
Restart=always

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now degimono
systemctl status degimono
journalctl -u degimono -f             # ログ確認
```

## 6. 動作確認

1. ラズパイ上: `curl http://localhost:5000/healthz` → `{"status":"ok"}`
2. PCのブラウザ: `http://<ラズパイIP>:5000/` が開き、部品が検索できる。
3. `http://<ラズパイIP>:5000/m5-dummy` でQR出庫を試し、在庫が減る・発注点以下でアラートが出る。
4. MQTT確認（ブローカー稼働・受信処理）:
   ```bash
   # 方式B
   mosquitto_sub -t degimono/status &
   mosquitto_pub -t degimono/checkout -m '{"employee_id":"1001","department":"製造部","part_id":"JK-5070","quantity":1}'
   # 方式A（コンテナ内で実行）
   docker exec degimono-mqtt mosquitto_pub -t degimono/checkout -m '{"employee_id":"1001","department":"製造部","part_id":"JK-5070","quantity":1}'
   ```
   `degimono/status` に `{"status":"ok", ...}` が返り、画面の在庫が減っていればOK。
5. ラズパイ再起動後も自動で立ち上がること（`sudo reboot` → 数分後に画面を開く）。

## 8. 保守

### 8.1 バックアップ
DBは `data/degimono.db` の1ファイル。定期的にコピーしておく。
```bash
sudo apt install -y sqlite3
mkdir -p ~/backup
sqlite3 ~/degimono/data/degimono.db ".backup '$HOME/backup/degimono_$(date +%F).db'"
```
毎日自動化する例（`crontab -e`）:
```
0 2 * * * sqlite3 $HOME/degimono/data/degimono.db ".backup '$HOME/backup/degimono_$(date +\%F).db'"
```
復元は、停止 → `data/degimono.db` を差し替え → 起動。

### 8.2 アプリの更新
1. PCで修正したファイルを `scp`（3章）でラズパイへ送る。
2. 反映:
   - 方式A: `docker compose up -d --build`
   - 方式B: `sudo systemctl restart degimono`
3. **DBのテーブル構成を変えた場合は注意**: 現状は `CREATE TABLE IF NOT EXISTS` のみで、既存DBへの列追加は自動では行われない。更新前に必ずバックアップを取り、必要ならマイグレーション手順をこの手順書に追記する。

### 8.3 DBの初期化（デモデータへ戻す／入れ直す）
```bash
# 方式A
docker compose down && rm data/degimono.db && docker compose up -d
# 方式B
sudo systemctl stop degimono && rm data/degimono.db && sudo systemctl start degimono
```
※ 全データが消える。本番では実行前にバックアップを取る。

### 8.4 セキュリティ
- ポート5000（Web）と1883（MQTT・認証なし）は**社内LAN内のみ**で使う。ルーターでインターネットへ公開しない。
- 画面・APIに認証はない。必要になったらこの手順書に追記する。
- 従業員の追加・変更は現状 `app.py` の `EMPLOYEES` 編集が必要（初回DB作成時のみ投入。運用中の変更手順は未整備）。

## 10. トラブルシューティング

| 症状 | 確認・対処 |
|---|---|
| 画面が開かない | ラズパイのIP確認、同じLANか、`docker compose ps` / `systemctl status degimono`、ポート5000 |
| `docker: permission denied` | `sudo usermod -aG docker $USER` 後にログインし直す |
| M5から送れない | 固定IPを指定しているか、同一LANか、`mosquitto_pub` で手元から送って確認 |
| MQTTで在庫が変わらない | `docker compose logs web` / `journalctl -u degimono` で `[MQTT] connected` が出ているか。出なければブローカー設定（5.2）を確認 |
| 日時が9時間ずれる | `timedatectl` でタイムゾーン確認（`sudo timedatectl set-timezone Asia/Tokyo`）。Dockerは `TZ` 指定済み |
| CSVが文字化け | Excelで開く場合はBOM付きUTF-8のため通常は問題なし。ダブルクリックで開いて化ける場合は「データ→テキストから」で UTF-8 を指定 |
| DBが壊れた/戻したい | バックアップから復元（8.1） |
