# ラズパイ 構築・運用手順書

在庫管理システム（Node-RED + MQTT）をラズパイで動かすための手順書。**機能追加・仕様変更のたびに更新**する（末尾の「更新履歴」に追記）。

フローの中身（タブ、API、データの形）は `nodered/README.md` と `nodered/自作用の方針.md` にある。

---

## 1. 前提・構成

| 項目 | 内容 |
|---|---|
| 機種 | Raspberry Pi 3B+ / 4 / 5 推奨（Zero系は非推奨） |
| OS | Raspberry Pi OS (64bit) Bookworm 以降 |
| ネットワーク | 有線LAN推奨。M5StickC・業務PCと同じLANに接続 |
| Web画面・API | Node-RED（ポート1880）。ラズパイに直接インストールし、PM2 で常駐 |
| MQTTブローカー | Mosquitto（ポート1883）。Docker のコンテナ `degimono-mqtt` |
| データ | Node-RED のグローバルコンテキスト `degimono`。`~/.node-red/context/global/global.json` に保存（DB は使わない） |

開発の正は手元のリポジトリ（`nodered/make_flows.js` と画面の `index.html`、`m5_dummy.html`）。ここを直して `flows.json` を作り、ラズパイへ入れる。ラズパイのエディタで完成品のタブを直しても、次に入れ直すと上書きされる。

> 2026-10-28 まで使っていた Flask 版（`app.py`、SQLite）は削除した。必要になったら、git の最初のコミット `7a459e0` から取り出せる。作り直すときは Node-RED 版を正として移植する。

## 2. ラズパイの初期準備

1. Raspberry Pi Imager で Raspberry Pi OS (64bit) を書き込む。設定画面でホスト名、ユーザー名/パスワード、WiFiまたは有線、**SSH有効化**、ロケール（`Asia/Tokyo`）を済ませる。
2. 起動後、PCからSSH接続して更新する。
   ```bash
   ssh <ユーザー名>@<ラズパイIP>
   sudo apt update && sudo apt full-upgrade -y
   ```
3. **IPアドレスを固定する**（M5StickCがラズパイを見つけられるようにするため）。
   - 推奨: ルーターのDHCP設定で、ラズパイのMACアドレスに固定IPを割り当てる（予約）。
   - ルーターで設定できない場合は、ラズパイ側で設定（例: 有線）:
     ```bash
     nmcli con show                       # 接続名を確認
     sudo nmcli con mod "<接続名>" ipv4.method manual \
       ipv4.addresses 192.168.x.x/24 ipv4.gateway 192.168.x.1 ipv4.dns 192.168.x.1
     sudo nmcli con up "<接続名>"
     ```
   - M5StickC には mDNS 名ではなく**固定IP**を設定する（mDNS名はM5側で解決できないことがあるため）。

### 2.1 実機の接続情報（記録）

| 項目 | 内容 |
|---|---|
| ホスト名 | `raspberrypi`（mDNS: `raspberrypi.local`） |
| ユーザー名 | `raspi` |
| OS / 機種 | Debian 12 (bookworm) 64bit / aarch64、メモリ 8GB |
| タイムゾーン | Asia/Tokyo（設定済み） |
| 有線LAN（eth0） | PCと直結用に固定IP `192.168.50.2/24`（nmcliで手動設定） |
| Wi-Fi（wlan0） | `10.9.2.231/24`（DHCP。PC側Wi-Fi `10.22.x.x` とは別セグメント） |
| PC側（イーサネット） | `192.168.50.1/24`（直結用に手動設定） |
| SSH接続 | `ssh raspi@192.168.50.2`（PCの `id_rsa.pub` を登録済み・鍵認証。`sudo` はパスワード不要） |
| Node-RED | `http://192.168.50.2:1880/`（PM2 のプロセス名 `node-red`、`~/.node-red`） |
| Mosquitto | `~/degimono`（`docker-compose.yml` と `mosquitto/`） |
| バックアップ置き場 | `~/backup` |

> 直結の経緯: PC Wi-Fi とラズパイ Wi-Fi が別ネットワークで通信できず、LANケーブル直結＋固定IP（192.168.50.x）で接続した。`raspberrypi.local` は PC の `ssh` から名前解決できなかったので IP 直指定。
> M5StickC に設定する「固定IP」は、運用する実LAN側のIPで別途決める（上記 192.168.50.2 は直結用の暫定値）。

#### 直結の設定方法（PC側）：「代替の構成」を使う（採用）
PC の `イーサネット` は **DHCP（自動取得）のまま** にして、「代替の構成」に直結用の固定IPを登録する。DHCP のあるLANでは DHCP で IP が付き、DHCP がない直結のときだけ代替の構成の `192.168.50.1` が使われる。ケーブルを差し替えても設定変更は不要。

**設定手順**（管理者権限が必要）
1. （すでに固定IPを付けている場合のみ）管理者の PowerShell で DHCP に戻す。InterfaceIndex は `Get-NetAdapter` で確認（2026-10-21 時点は 21）。
   ```powershell
   Remove-NetIPAddress -InterfaceIndex 21 -IPAddress 192.168.50.1 -Confirm:$false
   Set-NetIPInterface -InterfaceIndex 21 -Dhcp Enabled
   ```
2. 「ネットワーク接続」（`ncpa.cpl`）→ `イーサネット` を右クリック → プロパティ → 「インターネット プロトコル バージョン 4 (TCP/IPv4)」→ プロパティ。
3. 「IP アドレスを自動的に取得する」を選ぶと **「代替の構成」タブ** が出る。
4. 「代替の構成」→「ユーザー構成」→ IPアドレス `192.168.50.1`、サブネットマスク `255.255.255.0`（ゲートウェイ・DNS は空欄）→ OK。

**確認**: 直結したまま `Get-NetIPInterface -InterfaceIndex 21 -AddressFamily IPv4` で `Dhcp` が `Enabled`、`ipconfig` で `192.168.50.1` が付いていること。DHCP が応答しない状態から IP が付くまで、ケーブルを挿して **1分ほど** かかることがある。

> ⚠️ 2026-10-21 時点では、この方式は実機で未確認（Windows 標準機能だが、本環境での動作確認はまだ）。確認できたらここを更新する。
> 参考（採用しなかった方式）: `New-NetIPAddress` で固定IPを付ける方法は、DHCP が無効になり、別のLANへ挿し直すと通信できなくなる。戻すときは上記の手順1のコマンドを使う。
> ラズパイ側（eth0 の 192.168.50.2）は、実LANへ接続するときに 2章の3 の手順で実LAN用の固定IPへ変更する（直結用のままだと実LANで使えない）。

## 3. 新しいラズパイに構築する

今のラズパイは構築済み。別のラズパイに作り直すときの手順。

### 3.1 Mosquitto（Docker）
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER          # 一度ログアウトして入り直す
```
PC のリポジトリから、ブローカーの設定を送って起動する。
```powershell
ssh <ユーザー名>@<ラズパイIP> "mkdir -p ~/degimono"
scp -r docker-compose.yml mosquitto <ユーザー名>@<ラズパイIP>:~/degimono/
```
```bash
cd ~/degimono && docker compose up -d
docker compose ps                      # degimono-mqtt が Up であること
```
- `restart: unless-stopped` なので、ラズパイを再起動しても立ち上がる。
- OS の apt 版 mosquitto がポート1883を使っていると起動に失敗する。`sudo systemctl disable --now mosquitto` で止める。

### 3.2 Node-RED
公式のスクリプトで入れる。
```bash
bash <(curl -sL https://github.com/node-red/linux-installers/releases/latest/download/update-nodejs-and-nodered-deb)
```
常駐のさせ方は次のどちらか。今のラズパイは PM2 を使っている。
- systemd: `sudo systemctl enable --now nodered`
- PM2: `sudo npm install -g pm2` → `pm2 start node-red` → `pm2 save` → `pm2 startup`（表示されたコマンドを実行）

### 3.3 データをファイルに保存する設定
`~/.node-red/settings.js` の `contextStorage` を有効にする（コメントになっている例のすぐ上に足す）。
```js
    contextStorage: {
        default: { module: "localfilesystem" },
    },
```
変更したら Node-RED を再起動する（`pm2 restart node-red` または `sudo systemctl restart nodered`）。これがないと、再起動のたびにデータが消える。

### 3.4 フローを入れる
4章の手順で入れる。初回はデータがないので、起動時にデモデータが入る。

## 4. フローの更新（いつもの作業）

PC のリポジトリで画面かフローを直したら、`nodered` フォルダで次を実行する。

```bash
node make_flows.js     # flows.json と flows_screen.json を作る
node deploy.js         # ラズパイ（既定 192.168.50.2）の Node-RED に入れる。別のホストは node deploy.js <IP>
```

- `deploy.js` は、ID が `dc` で始まるノード（完成品）だけを入れ替える。エディタで作ったほかのタブは残る。
- データ（在庫・履歴）は入れ替えても消えない。
- エディタを開いている人は再読み込み（F5）する。古い画面のままデプロイすると、入れ直した分が古いものに戻る。
- エディタから入れる場合: 右上メニュー →「読み込み」で `flows.json` を選び、同じノードがあると聞かれたら「置換」を選んでデプロイする。

## 5. 動作確認

| 確認すること | 方法 |
|---|---|
| 画面が開く | `http://<ラズパイIP>:1880/app` |
| M5 のダミー画面で出庫できる | `http://<ラズパイIP>:1880/m5-dummy`。注記に「通知: 接続中」と出ていれば、発注点以下の通知も表示される |
| CSV が取れる | `http://<ラズパイIP>:1880/download/history.csv` |
| データを見る | エディタの右のサイドバー「コンテキストデータ」→「グローバル」の `degimono`（更新ボタンで最新になる） |
| 再起動してもデータが残る | `pm2 restart node-red` のあと、画面で在庫が変わっていないこと |

**MQTT で試す**（M5 がなくても、ブローカーのコンテナで送受信できる。ターミナルを2つ使う）
```bash
# 1つ目: 結果と通知を待つ（# で全トピック）
ssh raspi@192.168.50.2 "docker exec degimono-mqtt mosquitto_sub -t 'degimono/#' -v"

# 2つ目: 出庫を投げる
ssh raspi@192.168.50.2 "docker exec degimono-mqtt mosquitto_pub -t degimono/checkout -m '{\"part_id\":\"AB-1234\",\"quantity\":1,\"user_name\":\"山田太郎\",\"department\":\"製造部\"}'"
```
`degimono/status` に結果が返り、発注点以下になれば `degimono/alert` に通知が届く。

## 6. M5StickC の接続設定（暫定・M5仕様確定後に更新）

- 接続先: ラズパイの**固定IP**。M5が接続するWiFiは、ラズパイと同じLAN（同一セグメント）にする。
- MQTT: ブローカー `<ラズパイIP>:1883`
  | トピック | 向き | 中身 |
  |---|---|---|
  | `degimono/checkout` | M5 → ラズパイ | 出庫。`{part_id, quantity, user_name（または employee_id）, department}` |
  | `degimono/status` | ラズパイ → M5 | 出庫の結果。`{status, message, stock, alert, ...}` |
  | `degimono/alert` | ラズパイ → M5 | 発注点以下の通知。`text` をそのまま画面に出す |
- HTTP でも出庫できる: `POST http://<ラズパイIP>:1880/api/checkout`（中身は MQTT と同じ）
- サンプル: `m5stickc_mqtt_sample.ino`（M5Unified、日本語フォント）

## 7. 保守

### 7.1 バックアップ
データは `~/.node-red/context/global/global.json` の1ファイル。
```bash
mkdir -p ~/backup
cp ~/.node-red/context/global/global.json ~/backup/global_$(date +%F).json
```
毎日自動化する例（`crontab -e`）:
```
0 2 * * * cp $HOME/.node-red/context/global/global.json $HOME/backup/global_$(date +\%F).json
```
復元: `pm2 stop node-red` → ファイルを差し替え → `pm2 start node-red`（動かしたまま差し替えると、Node-RED の保存で上書きされる）。

### 7.2 データをデモの状態に戻す
エディタの「データ準備（完成品）」タブの「デモデータに戻す」の左のボタンを押す。従業員17人、部品6件、入荷待ち3件に戻る。全データが消えるので、本番では先にバックアップを取る。

### 7.3 従業員・部品を変える
画面から追加できるのは部品だけ（部品登録）。従業員の変更と初期データの差し替えは、`nodered/make_flows.js` の「デモデータを作る」を直して入れ直し（4章）、7.2 で入れ直す。運用中に従業員を足す画面はまだない。

### 7.4 セキュリティ
- ポート1880（画面・API・エディタ）と1883（MQTT）は認証がない。**社内LAN内だけ**で使い、インターネットへ公開しない。
- エディタ（`http://<ラズパイIP>:1880/`）は誰でもフローを書き換えられる。必要になったら `settings.js` の `adminAuth` でパスワードを付ける。

## 8. 自作版を作るとき（授業用）

完成品と同じ機能を自分で作るときの方針は `nodered/自作用の方針.md`。

1. 完成品の6つのタブ（末尾が「（完成品）」）をすべて無効にし、デプロイする（タブ名をダブルクリック →「無効」）。自作のフローと URL（`/app`、`/api/...`）が重なると、どちらが応答するか分からなくなるため。
2. エディタの右上メニュー →「読み込み」で `nodered/flows_screen.json`（画面タブだけ）を読み込む。HTML はこれを使う。
3. グローバルコンテキストのキーを完成品と同じ `degimono` にすると、データを引き継げる。
4. 詰まったら完成品のタブを開いて見比べる。共通処理は「共通処理（完成品）」タブにある。

完成品に戻すときは、自作のタブを無効にして完成品のタブを有効に戻す。

> ⚠️ 自作中に `node deploy.js` で完成品を入れ直すと、完成品のタブが有効な状態に戻り、自作のフローと URL が重なる。入れ直したら、もう一度完成品のタブを無効にする。

## 11. トラブルシューティング

| 症状 | 確認・対処 |
|---|---|
| 画面が開かない | ラズパイのIP、同じLANか、`pm2 ls` で `node-red` が online か、ポート1880 |
| Node-RED のログを見たい | `pm2 logs node-red --lines 50 --nostream` |
| デプロイしたのにエディタが古い | エディタを再読み込み（F5） |
| M5から送れない | 固定IPを指定しているか、同一LANか、5章の `mosquitto_pub` で手元から送って確認 |
| MQTT で在庫が変わらない | `docker compose ps`（`~/degimono`）でブローカーが Up か。エディタの出庫タブの `mqtt in` に「接続済」と出ているか |
| 出庫したのに履歴に残らない | 社員名（`user_name`）か社員ID（`employee_id`）が従業員マスターと一致しているか（一致しないと 404 になる） |
| 再起動でデータが消える | `settings.js` の `contextStorage`（3.3）が有効か |
| `docker: permission denied` | `sudo usermod -aG docker $USER` 後にログインし直す |
| 日時が9時間ずれる | `timedatectl` でタイムゾーン確認（`sudo timedatectl set-timezone Asia/Tokyo`） |
| CSVが文字化け | BOM付きUTF-8のため通常は問題なし。化ける場合はExcelの「データ→テキストから」で UTF-8 を指定 |
